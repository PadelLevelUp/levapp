# B-054 — Nine model-versus-migration differences on a clean database

**Source:** found while verifying PAD-265 (Session A, 2026-09-10). PAD-265 keeps autogenerate off
`apscheduler_jobs`; these nine differences remained, and they have nothing to do with APScheduler.

**Running `flask db migrate` today drafts a revision that DROPS `uq_club_join_request_pending`
and `uq_player_claim_request_pending`, the two partial unique indexes that enforce "one pending
join request per coach and club" and "one pending claim per player". Until this entry is
resolved, read every autogenerated revision and delete those drops before committing it.**

**What happens:** on a freshly migrated database (`levelup_e2e_a`, 2026-09-10), `flask db check`
exits 1 with these nine operations. Each is a database object a migration created that no model
declares, or a model attribute that disagrees with the column the migration made:

| # | Autogenerate proposes | The database has | The model declares |
|---|---|---|---|
| 1 | `modify_nullable` `bulk_imports.created_at` → nullable | `NOT NULL DEFAULT now()` | the `model.Model` mixin's nullable `created_at` |
| 2 | `remove_index` `ix_club_join_requests_club_id` | btree `(club_id)` (migration `c1d2e3f4a5b6`) | no index |
| 3 | `remove_index` `ix_club_join_requests_coach_id` | btree `(coach_id)` (`c1d2e3f4a5b6`) | no index |
| 4 | **`remove_index` `uq_club_join_request_pending`** | UNIQUE `(club_id, coach_id) WHERE status = 'pending'` (`c1d2e3f4a5b6`) | nothing |
| 5 | `remove_index` `ix_coach_join_tokens_coach_id` | btree `(coach_id)` (`d2e3f4a5b6c7`) | no index |
| 6 | `remove_constraint` `uq_device_tokens_token` | UNIQUE constraint `(token)` (`c5d6e7f8a9b0`) | `token` `unique=True, index=True` (one unique index) |
| 7 | `remove_index` `ix_device_tokens_token` | non-unique btree `(token)` (`c5d6e7f8a9b0`) | same as 6 |
| 8 | `add_index` `ix_device_tokens_token` (unique) | — | same as 6 |
| 9 | **`remove_index` `uq_player_claim_request_pending`** | UNIQUE `(player_id) WHERE status = 'pending'` (`e3f4a5b6c7d8`) | `player_id` `index=True` only |

**Why it matters:** PAD-220's `flask db check` drift gate fails on a clean database until these
are reconciled. And every autogenerated revision carries drops that would remove data-integrity
guards (rows 4 and 9) or churn working indexes.

**Fix (owner: PAD-220, Session B):** declare the indexes on the models. The partial unique ones
go in `__table_args__` as `Index(name, ..., unique=True, postgresql_where=text("status = 'pending'"))`.
Make `bulk_imports.created_at` `nullable=False` with a `now()` server default. For
`device_tokens.token`, declare the existing `UniqueConstraint("token", name="uq_device_tokens_token")`
plus the plain `ix_device_tokens_token` index instead of `unique=True, index=True`. The database
already holds the intended state, so this can likely be done on the models alone, with no
migration; confirm with `flask db check` on a freshly migrated database.

Related: PAD-265 (where it was found), PAD-220.
