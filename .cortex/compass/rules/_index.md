# Rules — index

**Read this when:** you are about to write or edit project files — check whether a
rule's `governs` glob matches the target path first.

**What's here:**
- `R-NNN-<slug>.md` — one file per rule: title, source, governed globs, optional machine check.

**How to navigate:** follow `source:` to the atlas decision or bug justifying the
rule; `governs:` names the constrained paths; `check:` is the testable predicate.
- [R-001 — Recurring lessons never pre-create instance rows](R-001-lazy-instance-materialization.md) — instances appear on demand through `get_or_materialize_instance()`; never construct a `LessonInstance` for a recurring lesson yourself
- [R-002 — Levels, evaluation categories, exercises, notification config and player notes are coach-scoped](R-002-coach-scoped-data.md) — the same player carries different levels and evaluations from different coaches, so every query filters by coach
- [R-003 — All lessons belong to a club](R-003-club-scoped-lessons.md) — `lessons.club_id` cascades, and player and calendar queries filter by the coach's current club
- [R-004 — Many-to-many relationships use explicit association tables with an `id` primary key](R-004-association-tables-for-m2m.md) — not bare composite keys: these tables routinely carry extra fields (`side`, `role`)
- [R-005 — Business logic lives in `padel_app/services/`; route handlers stay thin](R-005-services-layer.md) — a handler in `modules/` calls the service and returns its result, nothing more
- [R-006 — Tests import service functions inside the test body](R-006-import-services-inside-tests.md) — a module-top service import creates circular imports across the suite
- [R-007 — DB work runs inside `with app.app_context():` — one context, one session](R-007-app-context-for-db-work.md) — the session is scoped per app context (PAD-291): a nested context's teardown used to close the OUTER session, leaving Postgres idle in transaction and hanging CI (B-068)
- [R-008 — Integration tests patch external I/O and inject `now=`](R-008-patch-io-inject-now.md) — mock Redis, push and the scheduler; never mock `datetime`, take a `now=` parameter instead
- [R-009 — JWT in the Authorization header everywhere, in `?token=` only on the SSE endpoint](R-009-jwt-query-string-only-for-sse.md) — `EventSource` cannot set headers, so `/api/app/events` is the single exception; no other endpoint reads a token from the URL
- [R-010 — Scheduler job ids follow the fixed naming scheme](R-010-scheduler-job-naming.md) — the extend and self-heal logic finds jobs by these exact names, so a renamed job is an invisible job
- [R-011 — Web imports use the `@/` alias, never relative `../../` paths](R-011-web-path-alias.md) — `@/` maps to `apps/web/src`; mobile defines its own `@/` pointing at `apps/mobile/src`, so the same import line means different files in the two shells
- [R-012 — All HTTP calls go through `@levelup/api`](R-012-api-through-levelup-api.md) — a direct axios call from a component bypasses auth refresh and breaks web/mobile parity
- [R-013 — Playwright locators follow role > placeholder > label > text > CSS](R-013-e2e-locator-priority.md) — `getByRole` first; a CSS class selector is the last resort
- [R-014 — Real-time updates arrive over SSE (`/api/app/events`); never poll](R-014-sse-not-polling.md) — a polling loop duplicates the SSE path and multiplies backend threads
- [R-015 — Web UI uses the Radix/shadcn primitives in `src/components/ui/`](R-015-shadcn-ui-primitives.md) — one primitive set is what keeps the design system enforceable; no competing UI library
- [R-016 — Messages are soft-deleted via `is_deleted`, never hard-deleted](R-016-soft-delete-messages.md) — the conversation renders a "Message deleted" placeholder in the row's place
- [R-017 — Conversation lookup goes through `Conversation.build_participant_key()`](R-017-conversation-participant-key.md) — sorted comma-separated user ids make the lookup idempotent; a hand-built key silently misses the existing conversation
- [R-018 — `(player_id, lesson_instance_id)` is unique on presences](R-018-presence-unique-per-instance.md) — update the existing row; never insert a second presence for the same player and occurrence
- [R-019 — `player_level_history` is append-only](R-019-level-history-append-only.md) — rows are never updated or deleted, and `player.level` is the latest by `assigned_at`
- [R-020 — A diverging instance records its diverging fields in `overridden_fields`](R-020-overridden-fields-tracking.md) — that JSON is how the frontend tells a custom value from an inherited one
- [R-021 — E2E tests are named `"US-XXX: description"`](R-021-e2e-test-naming.md) — traceability from a failing spec back to the user story
- [R-022 — The backend serialises API responses in camelCase](R-022-camelcase-api-responses.md) — `startTime`, `maxPlayers`, `coachId`; `@levelup/types` mirrors the shape exactly
- [R-023 — Two clocks: event timestamps are naive UTC, class times are naive Lisbon wall-clock](R-023-utc-in-backend.md) — compare each with its own clock (`utcnow_naive()` vs `club_now_naive()`) and cross only through the `CLUB_TZ` helpers; mixing them made every class deadline an hour late for six months
- [R-024 — Anything added to `apps/web` is added to `apps/mobile` in the same ticket](R-024-web-and-ios-ship-together.md) — web-only must be argued in the PR body AND the spec; mobile i18n is static-import, so a new namespace renders raw key paths until hand-added to `i18n.ts`
- [R-025 — On mobile a font weight is reached by naming the family, never by `fontWeight`](R-025-mobile-font-family-not-weight.md) — a bare `font-semibold` is inert and renders Regular; `resolveFontClass` collapses the weight names, and it is applied in the five places app text is rendered
- [R-026 — A clickable card or list row is a real control, not a styled div with onClick](R-026-clickable-cards-are-real-controls.md) — `onClick` plus `cursor-pointer` makes it a control: focusable, accessibly named, activatable by Enter AND Space (Space must `preventDefault()`), with a visible focus ring; `Pressable` with `role` and `accessibilityLabel` on iOS
- [R-027 — SSE fan-out is per-process: one gunicorn worker until a shared broker exists](R-027-sse-single-gunicorn-worker.md) — the subscriber registry lives in the process that accepted the connection, so a second worker silently drops events for everyone attached to the first; raise `--threads`, never `--workers`, until a shared broker exists
- [R-028 — The production database is backed up nightly off the VM, and the backup fails loudly or proves restorable](R-028-production-database-is-backed-up-nightly-off-the-vm.md) — Postgres is a bind mount on the prod VM's boot disk, so a lost disk is lost data: dump inside the container, upload to a private bucket off the VM, prune by age, and fail loudly rather than silently (B-080 ran months with no backup)
- [R-029 — When two things must mean the same, test them against each other](R-029-test-siblings-against-each-other.md) — where two things must agree (a web push and its native twin, a server derivation and the client fallback for it, two readers of one column), assert they agree with EACH OTHER, never each against a literal; a self-consistent payload can be individually defensible and still disagree with its sibling (B-073, PAD-324)
- [R-030 — Backend tests run on SQLite with foreign keys enforced and on Postgres built by the real migrations](R-030-backend-tests-on-both-databases.md) — both run on every PR and both must pass; test code never branches on the backend, and when the two disagree Postgres is the truth (issued as R-026 by mistake, renumbered by PAD-328)
- [R-031 — Resolving a spec conflict in a batch: establish which side is stale and take the current one](R-031-spec-conflict-in-a-batch.md) — integrating a branch cut before the last batch landed: for any rule number on both sides, work out which side is stale and take the CURRENT one (prefer HEAD only when you cannot tell), take the numbers unique to the branch, and prove the relation before accepting; keep-both applies only to append-only lists — ledger `_index.md`, `.maestro/config.yaml` flowsOrder, `packages/config/src/index.ts` (B-079)
- [R-032 — A test proves it found its subject before asserting anything about it](R-032-a-test-proves-it-found-its-subject.md) — governs the test trees and the workflows: a check that cannot find what it came for must fail loudly, because a vacuous pass is indistinguishable from a real one in CI
- [R-033 — Work you did not write is adopted under your name, with what you re-ran and what you inherited labelled apart](R-033-adopting-work-you-did-not-write.md) — a `Ran against:` line, an ownership paragraph and a "claimed by <source>, NOT re-verified by me" section on every adopted change; a process defect in the source is a separate ticket, never a reason to reject a correct one (PR #258, PAD-312, PAD-333)
- [R-034 — A fix is proven by four runs, not one](R-034-a-fix-is-proven-by-four-runs.md) — old code and new code, each with the triggering condition present and absent; the reproduction and no-regression cells are what make it conclusive, and a check that never fails against the defect has not been validated (PAD-312, B-058, PAD-314)
- [R-035 — Prove a procedure by enumerating its commands against what the system actually runs](R-035-enumerate-the-steps-before-trusting-the-summary.md) — the one-command deliverable is the point; write the runbook as the commands, name where each command's inputs come from at that point in the sequence, test unattended pipelines against the shapes you did not design for, and write the cases with no recovery as steps too (PAD-338, three instances by two sessions; confirmed 2026-09-16)
