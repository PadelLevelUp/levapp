## Purpose

Integration tests for the semi-automatic replacement-approval flow (spec `notifications.semi-auto-approval`) — a `NotificationConfig.invitation_mode` alternative to `"automatic"` where a declined/absent player's vacancy does NOT auto-invite replacements but instead creates a `ReplacementApprovalPrompt` the coach must act on. `TestInvitationModeConfig` pins the config round-trip (default `"automatic"`, `update_config`/`get_config_dict` round-trips `"semi_automatic"`, an invalid mode raises `BadRequest`). `TestReminderDeclineSemiAuto` pins that a reminder decline in semi-auto mode creates a `Vacancy` (`approval_status="pending"`), a `ReplacementApprovalPrompt` with a deduped ordered `queue_snapshot` of eligible candidates, and exactly ONE `replacement_approval`-type `Message` (sent by a disabled `"levelup-assistant"` system user in the assistant<->coach conversation) — with zero `NotificationEvent`s created (no invites sent yet), and that the assistant user is never listed as `active`. `TestConfirmPresencesBundle` covers the same flow triggered via `POST /api/app/class_instance/presences/confirm` with 2 absents in one call — both vacancies bundle into ONE prompt-message (`bundleId` shared across two `ReplacementApprovalPrompt` rows). `TestPromptIdempotency` pins re-triggering `trigger_invitations`/`create_approval_prompts` never duplicates prompts or messages — returns the existing bundle. `TestBatchProcessorGating` pins `process_invitation_batches` skips vacancies with `approval_status` `pending` or `dismissed`. The coach's decision, made via `replacement_approval_service.respond_to_approval(bundle_id, decision, coach_id)`, has four outcomes covered one-per-class: `TestYesNow` (`"yes_now"` → approves and sends immediately, marks the assistant message `responded`); `TestYesAtWindow` (`"yes_at_window"` → holds until the invitation window opens, verified both when the window is still closed — `process_invitation_batches` sends nothing — and already open at decision time, which behaves as an immediate `"yes_now"`); `TestDismiss` (`"dismiss"` → vacancy stays open but the engine never auto-sends for it; the coach's manual `send_manual_notifications` path is untouched; dismissal is terminal — a later `"yes_now"` on the same bundle is a `"stale"` no-op); `TestStale` (a decision on a vacancy already filled via another path returns `"stale"` and leaves the prompt `status="stale"` without creating events). `TestWaitingListGating` pins that a standing waiting-list candidate is disclosed in the prompt (`waitingListPlayerId`/`Name`) but gated — the fill does not proceed while `pending`, only after `"yes_now"` approval. `TestAutomaticModeUnchanged` is the regression guard: plain `"automatic"` mode still sends immediately with no prompts at all, both via `trigger_invitations` and via `respond_to_reminder`.
